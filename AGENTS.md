# Trackwise

A small team's tracker for tasks and goals: who owns what, where it stopped, what happens next. Intent is in `docs/BRIEF.md`; every build decision is locked in `docs/PLAN.md` (stack, routes, roles, schema, design tokens, steps). Follow the plan; if something in it is impossible, say so instead of choosing differently. The team's conventions are the Apex skills (`apex-architecture`, `apex-ui`, `apex-ux`, `apex-planning`); the reference implementation of the same conventions is the Clarity project at `C:\Users\max\clarity`.

- Next.js 16.4.1 with `cacheComponents` and `partialPrefetching` on. Session reads sit behind `<Suspense>` (each `(app)` page has a `loading.tsx`); never `use cache` task, goal or request data.
- Data access goes through `lib/dal/*` with a `Viewer` (`lib/viewer.ts`), scoped by `org_id` in SQL. Permissions are pure predicates in `lib/permissions.ts` (unit-tested). Mutations are server actions in `actions/`: zod parse → `requireViewer` → permission → transaction → `ActionResult` (`lib/action-result.ts`).
- Schema: `db/schema.ts`, applied with `npm run db:push` (no migrations folder; additive changes only once real data exists).
- Checks before calling anything done: `npm run typecheck` (runs `next typegen` first), `npm run lint`, `npm run test:unit`, `npm run build`, and the relevant walkthrough.
- Hosting: the team VPS runs it under pm2 on port 3015 (`ecosystem.config.js`, `deploy.sh`, run by the owner); the database is Postgres (Neon), reached through `DATABASE_URL`. Never deploy or push unless asked. Environment variables are listed in `.env.example`.
- Roles are per workspace: `admin`, `leader`, `member`, `stakeholder`. The people in a workspace are its **members**. Work is grouped only by **projects**, **goals** (a goal may have sub-goals, one level deep; a sub-goal's target date never passes its parent's) and **tasks**. There are no teams any more (docs/PLAN.md, 2026-10-30 log): the four team tables stay in `db/schema.ts` as unused legacy, and `npm run db:backfill-team-assignees` once copies old team memberships onto their tasks as direct assignments.
- Assignment is a set of people: `task_assignees`, no owner. `tasks.assignee_id` is legacy and unused; after `db:push` on a database that already has tasks, run `npm run db:backfill-assignees` once.
- A comment on a task is **open until someone resolves it** (`task_updates.resolved_at`), and a task cannot be completed or approved while a comment is open (`lib/tasks/transitions.ts`); every form says so before the save.
- What exists: sign-in (Google + magic link), workspaces with onboarding (skippable: Home shows how to get a workspace), invitations (links copyable; Home lists the ones waiting for your email), members and roles, profile and email preferences; tasks with the Resume card (next action, latest progress, blocker, evidence, open comments), one-form Update progress, status transitions with append-only history, comments with Resolve / Reopen, list and board views with URL filters that show when they are on (tinted controls, a "Filtered:" chip row, Clear all; the board's cards drag between columns to change status — `components/kanban.tsx`, drops that need a reason or an approver open the transition dialog) living as tabs on `/home` (`?view=list|board|projects|home`; the tabs themselves drag to reorder, the first tab is the landing, kept in the `trackwise.homeTabs` cookie — `lib/home-tabs.ts`; `/projects` redirects in, `/tasks` is gone), My Work, the add bar at the top of My Work, the List and Board tabs and active project/goal pages (`components/tasks/quick-add-task.tsx`; typed `!high` `@tomorrow` `@sam` shortcuts parsed in `lib/tasks/quick-add.ts`; N focuses it, More options opens the full dialog), the ⌘K palette and N/U shortcuts; projects and goals with sub-goals and real progress (rolled up from sub-goals and projects); the Members page (`/members`: roster with open work, invite); role-aware Home with the approval staging list for leaders; requests with leader decisions and conversion to tasks; in-app notifications with email by preference; Reports in the main navigation (three views — Executive health, Workload, My work — the active one in the brand colour; date presets plus Custom; avatar-only contributors; a sortable, colour-graded Contributions table; print and CSV export).
- Character counters appear only in the last fifth of a field's cap, as "N left" (`components/character-counter.tsx`); the caps live in `lib/limits.ts` and the server enforces them (`lib/sanitize.ts`).
- Turbopack sometimes keeps a stale server module graph after a new export is added to an existing module ("`x` is not a function" at runtime although typecheck passes). Restart the dev server (delete `.next/dev` first) before concluding anything.

- **Sign in:** `GET /api/test-login?as=<persona>&secret=<TEST_MODE_SECRET>&to=/home` on a dev server. Port **3015** is the owner's own `npm run dev`; it reloads your edits live, so use it (`--base=http://localhost:3015` / `TEST_BASE_URL=http://localhost:3015`). Next 16.4 refuses a second `next dev` in the same directory ("Another next dev server is already running"), so you can only run your own when 3015 is free: `BETTER_AUTH_URL=http://localhost:3021 npx next dev --port 3021` **with a matching `BETTER_AUTH_URL`**, because Better Auth redirects (sign-out, magic links) go to `BETTER_AUTH_URL`. The secret is in `.env.local`: **do not read `.env*` yourself** (denied in `.claude/settings.json`); the scripts pick it up. Rules and guards are in `lib/test-mode.ts`: dev builds only (a production build answers 404), timing-safe secret check, only these personas. It inserts a 12-hour database session plus the `better-auth.session_token` cookie, and sets the persona's workspace as active.
- **Accounts:** `npm run test:seed` (create / reset, rewrite `docs/TEST-ACCOUNTS.md`), `npm run test:status`, `npm run test:tidy` (put both workspaces back to the seeded state, remove workspaces a run created), `npm run test:clean` (delete both workspaces and every `.test` account).
- **See a screen:** `node scripts/test-browser.mjs <persona|public> [path] [--width=390 --height=844 --dark --full --base=…]` signs in with headless Chrome, prints horizontal overflow and console errors, and saves a PNG to `.test-shots/` (git-ignored). **Read the PNG to look at it.** Check phone (390×844) and desktop (1280×900), light and dark.
- **Run a whole flow:** `npm run test:walk` runs everything in `scripts/test-walkthrough/` and sums up; each script also runs alone and takes `--only=` to pick a part. `01-sign-in` (every persona lands on `/home` with the right navigation; the front door routes by audience; the test route refuses a bad secret, an unknown persona and an off-site `to`; sign-out) · `02-pages` (every screen as every persona, desktop light and phone dark, no errors or overflow; Reports in a worker's navigation and not a stakeholder's; old team addresses land on Members) · `03-task-flow` (create → update → block → unblock → approval → sent back → approved → reopened; history lists every event) · `04-requests` (submit → defer → approve → convert; the requester follows it) · `05-roles` (what each role may not do; another workspace sees nothing by id or by list) · `06-workspace` (invitations in every state, roles, remove and leave, delete a throwaway workspace, notifications, profile) · `07-planning` (a goal, a project under it, a task from the project, status changes) · `08-sub-goals` (a sub-goal from a goal page, the deadline rule both ways, roll-up of its task into the parent, the picker label, who may not) · `09-comments` (a task with open comments can't be completed or approved until each is resolved; reopen; the audit trail). To write another, import from `scripts/test-walkthrough/lib.mjs`.
- **Pickers in walkthroughs:** the assignees picker is a button that opens a searchable list of people; click the button by its text ("Unassigned", "You") or its label ("Assigned to"), click names inside `[cmdk-list]`, then press Escape. It is disabled until its options load, and `click` keeps trying until then.
- **Scope to the thing you mean.** Settings lists every member at once, so a page-wide `click("Remove")` presses the first row's button. `near: "Sam Dev"` keeps a click or a check inside that row.
- **Email:** nothing is ever sent to a `.test` address (`lib/mail`). In development a magic link, invitation or notification email to a `.test` address is printed to the dev server log instead, so the real email sign-in can be followed too. Notification emails follow each person's preferences (Settings) and are sent after the response with `after()`.

## Ground rules for test runs

- The scripts only ever reset or delete workspaces whose **every** member is a `.test` account, and refuse to touch a seeded slug that has a real member. Never sign in as, or act on, a non-test account.
- Leave things tidy: `npm run test:tidy` after a run (`npm run test:walk` does it itself).
- Port 3015 may be the owner's own `npm run dev`. Check who owns it before stopping anything; if it is theirs, use it and leave it running.
- This is Chrome emulating a phone. Real iPhone / Android behaviour (keyboard, safe areas, touch scrolling) is not proven by it; say so.
